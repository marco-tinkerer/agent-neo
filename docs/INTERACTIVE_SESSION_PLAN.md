# Interactive Session Enhancement Plan

**Date:** March 7, 2026
**Status:** PLANNED (Next Priority)
**Prepared by:** Gemini CLI

---

## 1. Objective
Before proceeding to Phase 2 (MQTT, Lambda, Polly), we will harden the **Direct Hailo Provider** by building a high-fidelity interactive CLI. This allows for empirical validation of the NPU inference speed, parser reliability, and tool-calling logic.

## 2. Key Enhancements

### 2.1 Streaming CLI Implementation
The current `main.py` is a simple blocking REPL. We will upgrade it to:
- **Token Streaming:** Print tokens as they are generated by the NPU for a "live" feel.
- **Tool Call Visualization:** Display clear status indicators (e.g., `[Neo is calling get_weather...]`) to distinguish between model thought and tool execution.
- **Async Input Loop:** Use an asynchronous input pattern to prevent blocking the event loop during inference.

### 2.2 Parser Hardening
Using the interactive session, we will monitor the `RepairingParser` to ensure:
- It correctly handles partial JSON chunks.
- It suppresses "Internal Thought" or `<tool_call>` tags from the final user-facing output.
- It recovers gracefully from malformed model output.

### 2.3 Resource Management
- **VDevice Lifecycle:** Ensure the `hailo_platform.VDevice` is released immediately on `SIGINT` (Ctrl+C) or `exit`.
- **Memory Monitoring:** Print basic peak memory usage after each turn to monitor the RPi 5's constraints.

## 3. Success Criteria
- [ ] Time-to-First-Token (TTFT) is under 2 seconds.
- [ ] Tool calls for "Time" and "Weather" are visually distinct from conversational text.
- [ ] No "leaking" of raw JSON or XML tags into the CLI.
- [ ] Stable 5+ turn conversation without NPU/Memory crashes.
